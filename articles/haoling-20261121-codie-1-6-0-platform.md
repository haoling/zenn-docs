CODE27 の Codie（ホログラム風のディスプレイに 3D キャラクターが住んでいる、AI コンパニオン端末）の **1.6.0** アップデートが来たんですが、これがもう衝撃で、触りながら変な声が出ました。

## そもそも CODE27 / Codie ってなんですか

たぶんこの記事を開いた人のほとんどは、CODE27 を知らないと思うので、先に説明させてください

**CODE27** は、円筒形の卓上 AI コンパニオン端末です。筒の中の 10.1 インチのディスプレイに 3D キャラクターが表示されて、そのキャラクターと**声で会話**できます。メーカー表記は「ホログラム風」のディスプレイで、ほんとうの空中映像ではなく、筒の中に画面があるタイプです。底面には 2.8 インチのタッチパネルがあり、キャラクターや衣装の切り替えはここで操作します

- 住んでいるキャラクターのことを **Codie（コーディー）** と呼びます。端末そのものも、ファンの間では Codie と呼ばれがちです
- Codie は自分の部屋（Codie スペース）を持っていて、衣装・表情・モーションが会話に合わせて変わります
- 会話の内容を覚えます（記憶カードや日記があります）
- 自作の 3D モデル（VRM / FBX / glTF など。MMD や VRoid のモデルも）を読み込めて、声も用意できます
- Bluetooth スピーカーとして音楽を流すと、RGB ライトと合わせて Codie が踊ります
- 120° の広角カメラと回転ベース（オプション）があり、こちらを振り向いてくれます
- 価格は本体のみで 99,800 円（税込）、回転ベースつきは 112,800 円（税込）。日本では Makuake の先行販売で、2026 年 2 月に始まりました

会話の頭脳はクラウドの AI で、Wi-Fi が必要です。ここ、ちょっと覚えておいてください。あとで効いてきます

### アップデート前は、正直そこまで差別化できていなかった

ここからは、はおりんの個人的な感想です。

1.5 系までの Codie は、とても出来のいい「**キャラクターと話せる端末**」でした。キャラクターの作り込みと、画面の綺麗さはほんとうに良いです。でも**機能の面で見ると、他の似た製品でもできることばかり**でした。会話する、覚えている、音楽を流す、アラームを鳴らす、ライトが光る。どれも、それ自体は同種の製品で既に実現されていることです

たとえば、この分野の先輩である **Gatebox** と並べてみます。公開情報で私が把握している範囲では、こんな感じです。

| | Gatebox | CODE27 |
| --- | --- | --- |
| 見た目 | 筒の中にキャラクターを投影する「キャラクター召喚装置」 | 筒の中のディスプレイにキャラクターを表示 |
| 標準キャラ | 逢妻ヒカリ | Codie（複数キャラ、自作モデルも可） |
| できること | 挨拶、雑談、天気や時間の案内、スマートホーム連携、LINE での連絡 | 会話、記憶、音楽、アラーム、ライト |
| 自作キャラ | MMD / Unity で作ったキャラを Gatebox Video などで楽しめる | 3D モデルを読み込める |
| 価格（発売時） | 量産モデルは 15 万円（税抜）、のちに 12 万円（税込）に値下げ | 99,800 円（税込・本体のみ） |

Gatebox は 2016 年の限定モデルから続く老舗で、「キャラクターと暮らす」という体験を早い時期に商品化した偉大な先輩です。私も、あの世界観には強い影響を受けています。CODE27 は、そこに「自作キャラの持ち込みやすさ」と「LLM による自由な会話」を足したもの、というのが私の理解でした。（Gatebox の現在の機能は、この記事を書く時点では確認できていません。あくまで発売当時の公開情報での比較です）

つまり、**これは「機能の差」というより「体験の質の差」で勝負している製品**でした。それはそれで素晴らしい。でも、エンジニアの私からは、「便利なおしゃべり家電が一個増えた」の延長に見えていたのも事実です

だから 1.6.0 が来たとき、驚いたんです

## 何が入ったのか

目玉は **LAN API** です。端末の「Lab > API」から有効にすると、同じ LAN 内のスクリプトやアプリから Codie を叩けるようになります。

配布された API ガイドのパッケージによると、規模はこんな感じです。

- OpenAPI で定義された **121 パス / 159 操作**
- 認証はペアリング（端末にコードが出る）→ 以降のリクエストは **HMAC 署名が必須**
- 端末の状態、キャラクター、チャット履歴、記憶カード、日記、アラームなどの取得
- 衣装・音楽・ライトの操作
- 読み上げ（TTS）や、会話ターンの投入
- `/v1/ws/events` によるリアルタイムイベント

他にも、Hey Codie のウェイクワード、シームレス会話、PMX モデルの読み込み、多言語化、Lab > Providers でのカスタム LLM / ハイブリッド構成など、盛りだくさんです。でも今回いちばん語りたいのは API の話なので、そこに絞ります

## 外から Codie を動かせる

まず素直な方向、「外から Codie に何かさせる」です。

たとえば `POST /data/user/chat/turns` に会話ターンを投げると、Codie が応答を生成してくれます。出力を `device` にすれば端末でしゃべらせることもできますし、TTS のエンドポイントで「この文章をしゃべって」と読み上げさせることもできます。

つまり、**家の中の何かが起きたとき、Codie に喋らせる**ことが普通にできる。通知を読み上げるスピーカー、というだけでも便利ですが、Codie は「キャラ」なので、通知がそのキャラの口調で届くわけです。これは普通のスマートスピーカーにはない楽しさです

## 本当にやばいのは「Codie から外へ」

でも、私が「化けた」と感じたのは逆方向でした。

**外部ツール（tool integrations）**という仕組みがあります。流れはこうです。

1. `PUT /data/user/tool-integrations/{id}` で、ツールの定義（名前・説明・引数）を Codie に登録する
2. 自分のプログラムが `/v1/ws/tool-integrations/{id}/executor` に **WebSocket で接続して待つ**
3. 会話中に Codie が「このツールを使おう」と判断したら、WebSocket 越しに呼び出しが届く
4. 自分のプログラムが処理して、結果を返す

ポイントは、**接続するのが自分のプログラム側からだ**という点です。Codie の側から自宅サーバーに入ってくる必要がないので、NAT の内側にいても、ファイアウォールに穴を開けなくても動きます。Webhook の受け口を公開しなくていいのは、地味ですがとてもありがたい

注意点がひとつあって、ツールの定義は**新しい会話セッションを始めたときに固定**されます。登録したのに Codie が使ってくれない、と思ったら、まず新しい会話を始めてみてください

これで、Codie の LLM が「道具を呼べる」ようになります。Codie に話しかけて、裏で自分のシステムが動く。AI エージェントの Tool Use を、**ホログラムのキャラ**が喋りながらやってくれる、というのが私にはたまらなかった

## 公開当日にやったこと

こんなの、作らない理由がありません。1.6.0 が来た日に、さっそく 3 つやりました。

### ① Chrome 拡張「Codie Browser Hands」

Codie に PC の Chrome を触らせる拡張機能です。外部ツールとして、タブの一覧、ページを開く、本文を読む、クリック、入力、スクロールなどを登録します。

「このページ読んで」「Google で○○を検索して」と話しかけると、Codie が拡張経由で Chrome を操作します。拡張の Service Worker が直接 Codie に WebSocket で繋ぐので、中継サーバーは要りません

安全面は気を遣いました。クリックや入力は既定で確認ウィンドウが出ますし、パスワード欄には入力できません。購入・送信・削除のような危険そうな操作は、確認をオフにしていても必ず確認が出ます。

MIT ライセンスで GitHub に公開していて、CodieHub Workshop にも投稿しました。ユーザー投稿としては 2 件目です。

https://github.com/haoling/codie-browser-hands

まだベータ版で、ページによっては違うボタンを押してしまうこともあります。最後の「注文する」は、いまのところ自分で押してください

### ② Game Buddy に日本語を足した

公式が公開している Game Buddy（ゲーム画面を見て Codie がコメントしてくれる Windows アプリ）のソースに、日本語 UI とコメント、日本語 Wikipedia 参照を追加しました。

### ③ k8s で連携マイクロサービス

自宅の Kubernetes クラスタに、Codie と他のシステムを繋ぐマイクロサービスを作っている最中です。ここは、動いたらまた別の記事にします

## カメラや回転ベースが API の対象外なのは、どうでもいい

正直に書きます。今回の API には、カメラや回転ベースの制御は入っていません。それを見て「ハードウェアは触れないのか」とがっかりする人もいるかもしれない。

でも私は、**ただ API の対象外というだけだ**と思っています。

端末はカメラも回転ベースも持っていて、素養は十分にある。そして 121 パスもの API を、HMAC 署名つきで、OpenAPI のドキュメント込みで、リアルタイムイベントの WebSocket まで付けて出してきた。ここで大事なのは何が入ったかより、**開発元が「ここはオープンなプラットフォームにしますよ」という姿勢を示した**ことだと思うんです。

API を出す会社は、その後も API を育てます。今は無いものが次の更新で生えてくる可能性は十分にある。そう思わせてくれるだけの本気を、今回の更新から感じました

---

## まだわかっていないこと

最後に、盛りすぎないために。

- API はベータ版で、ガイドにも「全 API の実機検証完了を意味するものではない」と書かれています
- 私の拡張も、モック端末と実際の Chromium を使った E2E は通っていますが、実機での検証は途中です
- 外部ツールの定義が会話セッションで固定される仕様は、実際に作ってみると少し癖があります

それでも、「手を動かせる口」ができたことは間違いありません。同じ LAN に Codie がいる人は、ぜひ Lab > API を開いてみてください。ガイドには Python のサンプルも付いていて、ペアリングから最初の会話までは数分で通ります

Codie と何を繋ぐか、考えているだけで楽しいです。ではでは！
